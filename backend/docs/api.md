# Lattafa API reference (v1)

Base URL: `/api/v1` · JSON in/out · keys are camelCase and identical to `pos/src/data/types.ts`.

Everything runs on **one domain**: `/menu/` (public menu), `/pos/` (store tills), `/delegate/` (field sales, web) and
`/api/v1` (this API). The web apps call the API on the same origin, so no CORS set-up is needed for them.

## Conventions

| | |
|---|---|
| **Auth** | `Authorization: Bearer <token>` (Sanctum, 30-day, one live token per person per device). |
| **Device** | `X-Device-Id: <uuid>` — the till's own id. Once signed in, the token decides which device it is; the header can't borrow another till's identity. |
| **Ids** | UUIDs, generated by the client for anything created offline (that is what makes retries idempotent). `{id}` in a path must be a UUID, otherwise `404`. |
| **Money** | whole IQD integers; USD tender is a decimal with 2 places. |
| **Time** | epoch **milliseconds** everywhere (`createdAt`, `sold_at`, `serverTime`…). |
| **Errors** | `{"error":{"code":"…","params":{…}}}` (validation adds `"fields":{"path":["msg"]}`). `code` is stable and equals the POS message key `err.<code>`. |
| **Status codes** | 200/201 ok · 401 not signed in / bad credentials · 403 not allowed · 404 not found · 409 conflict · 422 business rule or validation · 423 account locked · 429 slow down |

`Accept: application/json` is not required, but send it anyway.

Legend: 🔓 public · 🔑 any signed-in user · `perm` needs that permission (Super Admin always has all).

## Setup & sign-in

| | Endpoint | Notes |
|---|---|---|
| 🔓 | `GET /setup/status` | `{setupDone}` |
| 🔓 | `POST /setup` | **Once only** (`409 setup_already_done` afterwards). Body: `store{name,phone,address,city}`, `rate`, `admin{name,username,password,pin}`, `demoData`, `deviceId`, `deviceName`. Passwords everywhere are free-form (any characters) — 4 characters minimum, 72 bytes maximum (`password_short` / `password_long`); PINs are 4–6 digits. Creates roles, Super Admin, settings, the first device (`ST1`) and optionally demo data. Returns `{token,user,device}`. |
| 🔓 | `POST /auth/login` | Username + password `{username,password,deviceId?,deviceName?,app?}`. A new device is registered by the sign-in itself (anyone's). `app` = `pos` (default) or `delegate`: tills get codes `ST1, ST2…`, delegate phones `DL1, DL2…` (the code prefixes receipt numbers). `app=admin` is the admin panel: only roles that include the admin panel (and the Super Admin) get in, and the computer is **never** registered as a till (`device` is `null`, the token is not tied to a device). |
| 🔓 | `POST /orders` | A shop ordering from the customer menu: `{shopName,phone,note?,items:[{variantId,qty}]}` → `{order:{number,placedAt}}`. No sign-in; **10 per IP per hour** (`429`). A size not on sale → `422 product_unavailable`; an empty basket → `422 nothing_to_order`. At most 60 lines and 500 of one size. The order is a request, not a sale: no prices, no stock moved. |
| 🔓 | `GET /auth/login-users?app=` | Tiles for the PIN screen — any device except a revoked `X-Device-Id` (`403 device_revoked`). `app=pos` (default) lists people whose role allows the POS; `app=delegate` lists delegates. |
| 🔓 | `POST /auth/pin-login` | `{userId,pin,app?,deviceName?}` with an `X-Device-Id`; the first good PIN on a new device registers it (`ST…` / `DL…`, named `deviceName`). Wrong PIN → `401 invalid_credentials {left}`; after N failures `423 account_locked {seconds}`. A role that doesn't allow that app → `403 app_not_allowed` (delegates can't sign in to the POS). Both sign-ins: 15 wrong ones from one IP in an hour → `429 too_many_requests {seconds}` for that IP. |
| 🔑 | `GET /auth/me` | The signed-in person: role, effective `permissions[]`, `limits`. |
| 🔑 | `POST /auth/refresh` · `POST /auth/logout` | Roll the token / sign out. |
| 🔑 | `POST /auth/approve` | Supervisor approval `{pin,permission}` → `{approver:{id,name}}`. 5 wrong tries then `429`. |
| 🔑 | `POST /auth/change-credentials` | `{currentPin,newPin?,newPassword?}` |

| | Endpoint | Notes |
|---|---|---|

## Field sales (delegates)

Delegates sell **the shop's own stock** (location `loc-store`), like a till on the road: a delegate sale
(`channel: "delegate"`) takes its bottles off the shop's shelf, at the wholesale or retail price — in dinars, or on a
dollar bill (`currency: "USD"`) at those prices converted at the bill's rate and rounded to 50 cents a bottle
(`SaleService::usdListPrice`). The phone sends where it was sold: the shop (`customerId`), a free-text place
(`note`) and, if the phone had GPS, `lat`/`lng`/`accuracyM` (impossible spots are dropped, the sale is kept).
The older van tools below still work (a van is a stock location `van:<userId>`), but the delegate app no longer uses them.
A delegate = an account whose role allows the `delegate` app and holds `delegate.sell` (never the Super Admin).

### Report center (admin panel → Reports)

`GET /reports/table/{type}?from=&to=` (ms; default today, shop time) returns every report in one shape, which the screen,
the Excel file and the PDF page all use: `{type, from, to, financial, columns: [{key, label, type}], rows, totals, summary}`.
`label` is an i18n key; column `type` is one of `text · name ({en,ar,ku}) · label (value is an i18n key) · enum:<prefix>
· day (Y-m-d) · date / datetime (ms) · int · iqd · money (in the row's currency) · usd · pct · items ([{name,label,qty}]) ·
map ("lat,lng")`. Cost, profit and margin columns
(and their values) are only sent with `reports.financial`.

| Type | Needs | What |
|---|---|---|
| `sales-by-day` | `reports.view` | bills, bottles, takings, discounts, refunds, net (+ cost, profit, margin) per day |
| `sales-by-product` | `reports.view` | per size: bottles after returns, returned, takings (bill lines, before whole-bill discounts) (+ cost, profit, margin) |
| `sales-by-brand` / `sales-by-category` | `reports.view` | the same lines per brand / product category, with each one's share |
| `sales-by-seller` | `reports.view` | per cashier/delegate (`channel`): bills, bottles, takings, average bill, discounts, refunds, net (+ cost, profit) |
| `profit-loss` | `reports.financial` | rows `pl.sales`, `pl.refunds`, `pl.net_sales`, `pl.cogs`, `pl.gross_profit`, each expense category, delegates' road expenses, `pl.expenses`, `pl.net_profit` (`kind`: line / subtotal / expense / total) |
| `expenses` | `expenses.view` | every expense (amount in its currency + in dinars); summary adds delegates' approved road expenses |
| `delegate-sales` | `delegates.manage` | every delegate bill, newest first: `date`, `delegate`, `soldTo` (shop), `area` (its city), `place` ("lat,lng" where the phone was, else the shop's map pin), `sold` (items), `units`, `amount` (dollars on a dollar bill, else dinars — see `currency`), `amountIQD`, `debt` (put on the shop's account), `number`. Summary: bills, dollars received, total in dinars, added to debt. |
| `delegate-commission` | `delegates.manage` | per delegate: bills, sales, refunds, net, `rate` %, commission = net × rate. Set a rate with `PUT /delegates/{id}/commission {pct: 0–100}` (logged as `delegate.commission`). |
| `debt-aging` | `customers.view` | as of now: each customer's balance split into 0–30 / 31–60 / 61–90 / over 90 days. Payments clear the oldest debt first, so the balance is made of the newest credit sales; debt no sale explains (an opening balance) counts as the oldest. |
| `stock-valuation` | `reports.financial` | as of now: per size, bottles in the shop and in vans, value at cost and at the shop price |
| `slow-movers` | `inventory.view` | sizes in stock that sold fewer than 2 bottles in the window, the longest unsold first (`lastSold`, `idleDays`) |
| `purchases` | `purchasing.view` | deliveries received from suppliers in the window |
| `shifts` | `shifts.view_all` | shifts opened in the window: float, takings, cash expected and counted, difference (open shifts worked out live) |

## Purchasing and expenses

Amounts here are numbers **in their own currency** (`currency`: `USD` or `IQD`, 2 decimals; dinar amounts are whole
dinars) with the dollar `rate` of that day, and where useful their value in dinars (`*IQD`). A supplier deals in one
currency; their orders and payments are in it, and it cannot change once they have orders or payments.

| Perm | Endpoint | Notes |
|---|---|---|
| `purchasing.view` | `GET /suppliers` | every supplier with `balance` (what the shop owes, in their currency) and `openOrders` |
| `purchasing.manage` | `POST /suppliers` · `PUT /suppliers/{id}` `{name, phone?, contact?, city?, currency, notes?, active?}` | `supplier_currency_locked` when changing the currency of a supplier with history |
| `purchasing.view` | `GET /suppliers/{id}/statement` | `{supplier, balance, rows}` — deliveries (+) and payments (−), newest first, each with the running `balance` |
| `purchasing.pay` | `POST /suppliers/{id}/payments` `{amount, method: cash\|bank\|other, note?, paidAt?, rate?, purchaseOrderId?}` · `DELETE /supplier-payments/{id}` | a deleted payment stays in the activity log |
| `purchasing.view` | `GET /purchase-orders?status=waiting\|received\|cancelled\|all&supplierId=` · `GET /purchase-orders/{id}` | statuses `open → partial → received`, or `closed` (part came, the rest never will) / `cancelled` (nothing came). One order also carries its `receipts` (deliveries). |
| `purchasing.manage` | `POST /purchase-orders` `{supplierId, rate?, note?, expectedAt?, lines: [{variantId, qty, unitCost}], receiveNow?}` | numbered `PO-000001`…; `receiveNow` receives everything in the same step (goods already here). `supplier_inactive` for a switched-off supplier. |

## Offline sync

### `POST /sync/push`

```json
{ "items": [ { "entity": "sale", "id": "<uuid>", "data": { …the till's record… } } ] }
```

≤ 200 items. Entities: `sale`, `return`, `shift`, `collection`, `customer`, `stock_movement`, and from delegate phones
`visit`, `stock_request`, `closing` (same bodies as the endpoints above). A delegate's sale carries `channel: "delegate"`;
the server takes the stock from **the shop** (`loc-store`), whatever location the phone claims, and keeps its
`currency` (`IQD`/`USD`) and `lat`/`lng`/`accuracyM`. A dollar price (`usdListPrice` of the retail or wholesale
price) is a valid list price, not a `price_mismatch`. Response:

```json
{ "serverTime": 1790643846389,
  "results": [ { "entity":"sale","id":"…","status":"ok","flags":["negative_stock"] } ] }
```

| status | meaning | till should |
|---|---|---|
| `ok` | applied | remove from outbox |
| `duplicate` | already applied (retry, or nothing new) | remove from outbox |
| `retry` | not yet possible (`sale_not_synced`) | keep, try again after the sale is sent |
| `rejected` | can never succeed — see `code` (`number_taken`, `unknown_entity`, `invalid_id`, `required_fields`, …) | mark failed, show to a manager |
| `error` | server hiccup | keep, retry later |

Sale review flags: `negative_stock`, `price_mismatch`, `total_mismatch`, `payment_mismatch`, `discount_over_limit`,
`credit_limit_exceeded`, `unknown_cashier`, `customer_missing`, `shift_missing`, `not_a_delegate` (a delegate-channel sale
from someone without `delegate.sell`).
A till can never set a customer's balance or points, or a product's cost — those stay server-owned.

### `GET /sync/pull?since=<ms>`

`since=0` (or omitted) = full snapshot. Returns `{serverTime, since, settings, roles, users, products, customers, deleted:{products,users,roles}, catalog:{products,variants}, device, counters, van}`. `catalog` counts the whole catalogue (not just the changes): a device whose copy holds a different number fetches everything again.
`device` is this till/phone (its `code`), `counters` the highest receipt number the server holds for it (a device whose
browser storage was wiped must not reuse `ST1-000001`). `van` is only set for a delegate: `{locationId, stock:{variantId:qty}, requests[], closings[]}`.
Store `serverTime` and send it as `since` next time. **Push before you pull.**
Users are listed without any credential material; cost prices follow the same visibility rule as `/products`.
